# 0.6.12：联通压缩音频预收与缓存恢复启动优化

## 行为与边界

已有USB会话、已绑定且收到实际F8语音按下后，完成当前连接FD02 hello初始化即可
排队发送FB=1，不再等待主机完成VOICE_ENABLE。没有USB会话、显式禁用语音、
不支持/失败的语音状态、等待旧流结束均不授权预收。

仅固件内部分离物理采集与产品音频流的开始：尚未授权交付时不发送SOURCE_BEGIN/START，
避免VOICE_ENABLE把预收误认为正在交付的旧流而进入waiting_idle。启用后才按原有RBP/3
发送START和编码数据；不改变线协议、codec配置或客户端接口。

- 保存完整ICO单元，40字节/320采样/20ms；320字节最多8单元即160ms。
- 一旦主机接受，按原始顺序排出，每次5ms调度最多排一个单元；实时新数据追加在后。
- 首次主机授权的等待预算250ms；缓冲满或超时则取消预收、停止遥控器录音并记录诊断。
- 未授权交付前松手直接取消本次预收；不在事后偷偷回放已经松开的短按。
- 明确的禁用与新的USB会话token使旧预收失效；既不跨会话也不跨BLE连接保留。
- 已交付后若出现缓冲溢出，以数据丢失关闭当前流/连接，不能掐掉前缀继续正常交付。
- 显式禁用由产品层的会话策略判断，替代0.6.11的连接级voice_armed标记；GUI重开
  产生新会话时也能区分初次协商与用户禁用。

同一绑定的联通缓存恢复、编译MTU=23时，使用新ATT bearer默认MTU23，不发送等值MTU
交换。常见拓扑只剩FD02 CCCD恢复和hello；有Service Changed/Protocol Mode时仍先恢复。
非缓存的首次发现、小米ATVV和其他MTU配置保留原流程。本次不会缩短无线建链前的时间，
也不宣称修复0x3E。实际提前多少需测试，不能把160ms容量说成必然提前160ms。
