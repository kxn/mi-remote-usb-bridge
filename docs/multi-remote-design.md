# 小米与联通遥控器适配方案

2026-09-16，按用户确认缩小范围后的实施设计。旧的运营商家族扩展草案由本文替代。
研究来源固定在 [f293c62](https://github.com/kxn/unicom-ble-remote-research/tree/f293c62)。不采用其中移动/接收器的描述符挑战检查。

## 1. 范围与应用接口

同一份 CH582F 固件支持原小米 RC003 路径和已测联通 `XFRSD0D_U_R01_846_40091` 路径；同时只连接一只。
没有移动、电信或讯飞全家族兼容承诺。名称不作为联通必要条件，也不根据品牌选择编码器。

板端接收与校验原始压缩音频，USB 沿用 RBP/3；Python/.NET 的音频解码接口返回 PCM16LE 不变。
底层原始音频事件依旧是编码数据。ICO 为新登记的 codec 2/revision 1，见 [契约](ico-codec-v1.md)。
主机需要安装可选原生 ICO 解码库；缺失时不接受 ICO，普通按键和 IMA 保持可用。
C 通用 decoder 同样增加 ICO：函数接口不变，扩展调用者持有的状态结构，并继续接受旧 IMA 结构大小；另提供独立 ICO C ABI。

## 2. 扫描与识别

- 用户 FIND 并手动选择设备，不自动配对扫描结果。
- 保留小米名称提示；可连接广播或扫描响应中携带有效名称、HIDS 或 FD00 提示的设备进入待检查候选，未识别设备 support=0。不能要求广播一定列出连接后的 GATT 服务；候选名称不参与最终兼容性确认。相同地址和地址类型合并为一项。
- 同地址/类型的后续 scan response 可补名称；名称校验 UTF-8，候选 ID 不因更新而变化。
- 连接、恢复加密后读取 HID Map、动态发现 Report Reference、属性与描述符；不硬编码样机句柄。
- 联通首版精确匹配已测 169 字节 Map，将缺少 Usage 等缺陷处理限定在这份描述符，不放宽通用 parser。
- 核对 01/03/FC/F8/F9/04 Input 与 FB/FA Output 各唯一，方向及通知/写入属性正确。
- 发现 FD00/FD02，核对 Notify 和 CCCD；订阅并等待已知主动消息 `10 01 4b 2a 03 02 04 00 02 03`。
- 先安装路由再订阅，FD02 通知可以早于 CCCD ACK。重复消息不重建活动连接或录音。
- 2 秒未收到消息只公布按键可用、语音未确认；仍接收迟到的正确消息。错误消息判为不兼容并断开。

FD02 消息仍不称为已破解的认证帧。这里只将它作为本机的行为指纹；可能拒绝其他实际兼容型号，是首版明确边界。

## 3. 联通运行路径

1. 已确认 profile 且应用启用语音后，正确 F8 `82 03 01` 加 17 个零触发 SOURCE_BEGIN，排队写 FB=01。
2. 所有 ATT 写入串行化。仅未被 SDK 接受的提交可重试；已接受的写入等待完成，不重复提交。
3. FC 每包 20 字节，三片 0/1/2 重组成 48 字节；检查组序号、回绕和尾部重复字段。
4. 首个完整有效组产生 START，随后传前 40 字节 ICO；每单元 320 samples，主机每次新录音重置 decoder。
5. 活动流每 5 秒重发 FB=01，要求近期仍收到音频；重发不改变 stream/epoch。
6. F8 松键、应用停录或停用排队写 FB=00。等待至少 300 ms 安静尾包窗口，最长 1 秒；半组尾包按数据丢失收口。
7. 长度、分片、尾部、键表或初始化消息不匹配时停止此配置，不尝试其他厂家命令。
8. 首版不提供脱离实体按键的主机主动开麦。TV 无 HID 输出的观察不解释为已确认红外专用。

研究实测无刷新约 20.7 秒，刷新达到 40 秒，一次长测试在 59.84 秒远端断连；不承诺超过 60 秒，不拼接自动续录。

## 4. 代码与内存

- 复用 `rc003_adapter.c` 的有界 GATT 发现与服务变化处理。内部历史名字暂保留，避免迁移整个 WCH/模拟器接口。
- `unicom_profile.inc` 存只读 Map 与键表，`unicom_runtime.inc` 存独立联通状态机；不建设通用插件框架。
- 公共 discovery 缓冲只有一份；联通新增 48 字节重组缓冲与小型状态。静态 RAM 增量 104 字节。
- 小米原有数据库缓存不变；联通每次重连重新发现与确认，复用绑定密钥，不要求重新配对。
- 键表登记 28 个已测 BLE 键；新增 Settings/Local/Channel/Digit/Star/Hash 逻辑 ID，TV 不公布为可用键。
- 原始键表、FC 数据、Map 来源在 `tests/fixtures/unicom/SOURCE.md`，主机解码源码来源及构建见 `client/c/ico/README.md`。

## 5. 验证与发布边界

自动检查包括完整动态发现、早到/迟到/缺失 FD02、错误帧、28 键、FC 抓包重放、序号回绕、停止排队和状态清理；原小米 reference adapter 回归保持通过。
产品服务器测试验证 ICO 能力协商、RBP 数据/样本计数及 END；Python/.NET 分别校验 396 帧的参考 PCM 哈希。
Release/Debug 均需通过链接器 RAM/栈预留断言。

这些是构建和模拟/抓包回放验证，不替代 CH582F 实机配对、按键、连续两次语音、休眠重连及长录音测试。
开发固件尚未替换 `releases/0.6.5`，不得把已有小米硬件验收结论直接移到联通实现上。

- 构建标识 `0.6.6-unicom-dev`；Release `build/fw-unicom/ch582f.bin` 为 207416 B，Debug `build/fw-unicom-debug/ch582f.bin` 为 211568 B。

- `tests/test_ico.py`：4 项通过，含 Python/C 两条解码路径的 396 帧 PCM 哈希、旧 C IMA ABI、缺失原生库时能力降级。

- .NET 5 项通过（包括 ICO 向量与原模拟器集成）；原端到端 42 项通过；桌面回归在 `tools/demo-venv` 中 12 项通过。

## 0.6.6 实机跟进

初版实测暴露两个回归：小米 Report 数量检查过严、联通广播未列出 HIDS 导致候选过滤。两者已修复。联通随后在 Map 首次读取阶段超时、SDK 0x86/5 密集出现；MTU=23 对照版用户确认好用，因此 0.6.6 将 MTU=23 设为默认。上面的“未刷板”条目保留为初版测试历史，最新验收边界见 [0.6.6 发布记录](../releases/0.6.6/README.md)。
